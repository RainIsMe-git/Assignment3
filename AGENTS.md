# Project collaboration

- Record each round of feedback supplied by the user as test feedback in `PLAYER_FEEDBACK.md`, preserving earlier rounds. Use the columns **Test feedback / Change / Effect**. Describe good, weak or unresolved effects using the actual feedback; do not replace that column with developer test results.
- Put automated and browser checks in `PROCESS.md`, separate from playtest feedback. Link significant changes there and keep README instructions current.
- Submission documents should be English-first, with an optional Chinese comparison at the end. Use concrete, natural prose instead of repetitive checklists or promotional claims.
- Do not invent participants, their actions, successful retests or recognition rates. The author confirmed that another person tried the game before an explanation, and that the supplied audio may be distributed with the public source repository.
